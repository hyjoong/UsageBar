# 0.10 기획: 작업 기록(일지)

상태: 결정 완료, 1주 차 구현 중 · 작성 2026-10-17 · 기준 버전 0.9.1

## 1. 목표와 범위

"작업 영수증" 창을 **"작업 기록"** 창으로 바꾸고 탭을 **오늘 / 7일 / 영수증**으로 나눈다. "오늘" 탭은 이 Mac에 이미 있는 기록을 합쳐 프로젝트별 일지를 만든다.

- 입력: Claude Code 세션 로그, Codex 세션 로그, 각 프로젝트의 git 커밋, 기존 작업 영수증
- 프로젝트별 출력: 작업 시간, 에이전트에게 한 주요 요청, 커밋, 바뀐 파일 수
- 내보내기: 스크럼 3줄 요약 복사, 마크다운 복사
- MVP 원칙: **AI 요약 없음(규칙 기반)**, **로컬에서만 동작**, 네트워크 요청 없음

하지 않는 것(0.10): AI 요약, 자동 전송(Slack·Notion 등), 다른 Mac과 동기화, 원격 저장소 API(GitHub) 조회, 일지 편집·저장.

나중에 별도 앱(WorkLog)으로 떼어낼 수 있게, 로그 해석·시간 계산·git 읽기·서식은 UI와 한도 조회 코드에 의존하지 않는 별도 Core 모듈에 둔다(§5).

## 2. 이 Mac의 로그 구조 (읽기 전용 확인 결과)

2026-10-17에 이 Mac에서 필드 이름과 개수만 집계했다. 본문은 열람·인용하지 않았다.

### 2.1 규모

| 위치 | 파일 수 | 전체 크기 | 가장 큰 파일 |
| --- | --- | --- | --- |
| `~/.claude/projects/<인코딩된 cwd>/<sessionId>.jsonl` | 52 | 127MB | 약 50MB |
| `~/.codex/sessions/YYYY/MM/DD/rollout-<시각>-<id>.jsonl` | 606 | 1.3GB | **약 459MB** |
| `~/.codex/archived_sessions/` | 243 | — | — |

현재 `LocalSessionLogs.scan`은 파일 전체를 메모리에 읽고 256MB 초과 파일은 건너뛴다. 일지에서는 이 방식이 통하지 않으므로 증분 파싱이 필수다(§9).

### 2.2 Claude Code (`~/.claude/projects`)

한 줄이 JSON 하나. 최상위 `type`으로 구분한다.

| 쓰려는 정보 | 필드 |
| --- | --- |
| 타임스탬프 | `timestamp` (ISO8601, 소수 초 포함) — `user`, `assistant`, `attachment`, `system`, `queue-operation`, `pr-link` 등에 있음 |
| 세션 | `sessionId`, `uuid`, `parentUuid` |
| 작업 폴더 | `cwd`, `gitBranch` (모든 `user`/`assistant` 줄). 디렉터리 이름은 경로의 `/`를 `-`로 바꾼 것이라 **복원이 모호** → 반드시 `cwd` 필드를 쓴다. `relocated.relocatedCwd`도 있음 |
| 서브에이전트 구분 | `isSidechain` |
| 사용자 프롬프트 | `type == "user"` 이고 `message.content`가 문자열이거나 `text` 블록인 줄. 도구 결과(`tool_result` 블록, `toolUseResult` 있음)는 제외 |
| 프롬프트 출처 | `origin.kind` (`human` / `peer` / `task-notification`), `turnOrigin`, `promptSource`(`sdk`/`system`), `isMeta`, `isCompactSummary` |
| 세션 제목 | `ai-title.aiTitle`, `custom-title.customTitle`, `last-prompt.lastPrompt` |
| 도구 호출 | `assistant`의 `message.content[]` 중 `type == "tool_use"`: `name`, `input` |
| 수정 파일 | `Edit`/`Write`(·`MultiEdit`·`NotebookEdit`)의 `input.file_path`. 결과 쪽 `toolUseResult.filePath`, `toolUseResult.type`(`create`/`update`), `toolUseResult.structuredPatch` |
| 셸로 바뀐 파일 | `toolUseResult.bashEditDiff.changedFiles` / `files` / `moreFiles` |
| git 동작 힌트 | `toolUseResult.gitOperation` (`commit`/`push`/`branch`/`pr` 키), `pr-link.prUrl`·`prNumber`·`prRepository` |
| 세션 합계 | `cost-state.totalLinesAdded`·`totalLinesRemoved`·`totalDuration` (일부 세션에만 있음) |
| 모델·토큰 | `message.model`, `message.usage` (기존 영수증 집계가 이미 사용) |

관찰 사항
- 사용자 문자열 중 `<`로 시작하는 것은 슬래시 명령·시스템 주입 태그다. 프롬프트에서 제외한다.
- 세션 폴더 안에 `tool-results/`, `memory/`, `custom-title.json` 등이 있다. `*.jsonl`이 아니므로 읽지 않는다.

### 2.3 Codex (`~/.codex/sessions`)

한 줄이 `{timestamp, type, payload, ordinal, metadata?}`.

| 쓰려는 정보 | 필드 |
| --- | --- |
| 타임스탬프 | 최상위 `timestamp`. 턴 단위로는 `event_msg/task_started.started_at`, `task_complete.completed_at`·`duration_ms`, `turn_aborted` |
| 세션·작업 폴더 | `session_meta.payload`: `id`, `session_id`, `cwd`, `git.branch`·`git.commit_hash`·`git.repository_url`, `originator`, `source`, `parent_thread_id`, `forked_from_id` |
| 턴별 폴더·시간대 | `turn_context.payload`: `cwd`, `workspace_roots`, `timezone`, `current_date`, `model` |
| 서브에이전트 구분 | `session_meta.source.subagent`, `parent_thread_id`, `agent_role` |
| 사용자 프롬프트 | `event_msg/item_completed`의 `item.type == "UserMessage"` (`content`) 또는 `response_item/message`의 `role == "user"`, `content[].type == "input_text"` |
| 프롬프트에서 뺄 것 | `<environment_context>`, `<heartbeat>`, `<recommended_plugins>` 같은 태그로 시작하는 주입 텍스트, `role == "developer"` |
| 도구 호출 | `response_item/function_call`·`custom_tool_call`: `name`, `arguments`/`input`; `item_completed`의 `CommandExecution`(`command`, `cwd`, `exit_code`, `duration`), `McpToolCall` |
| 수정 파일 | `item_completed`의 `item.type == "FileChange"`: `changes`가 **경로 → {`type`, `unified_diff`, `move_path`}** 딕셔너리. 키가 바로 파일 경로 |
| 세션 제목 | `~/.codex/session_index.jsonl`의 `thread_name` (`id`, `updated_at`) |

관찰 사항
- 한 rollout 파일이 여러 날에 걸쳐 이어 쓰인다(재개 세션). 날짜 폴더는 **시작일**이지 마지막 기록일이 아니다 → 파일 수정 시각으로 걸러야 한다.
- `compacted`·`world_state` 줄은 매우 크다. 문자열 사전 필터로 JSON 해석 전에 건너뛴다.

### 2.4 포맷 변화 대비

두 CLI 모두 필드가 자주 늘어난다(같은 `type` 안에서도 키 조합이 버전마다 다름). 해석기는 **알려진 필드만 선택적으로 읽고, 모르는 `type`은 무시**한다. 필수 필드(`timestamp`, `cwd`)가 없으면 그 줄만 버린다. CLI 버전(`version`, `cli_version`)은 진단용으로만 기록한다.

## 4. 화면 구성

창 제목: `작업 기록 · UsageBar` (영문 `Work Log · UsageBar`). 상단에 세그먼트 탭 **오늘 / 7일 / 영수증**. 마지막으로 연 탭을 기억한다.

### 4.1 오늘 탭

```
[◀]  10월 17일 (금)  [▶]                    [복사 ▾ 스크럼 3줄 | 마크다운]
총 3시간 40분 · 프로젝트 3 · 커밋 5 · 파일 23            (일부만 집계됨 ⓘ)

┌ UsageBar  main                         1시간 55분  Claude · Codex
│ ▁▁▇▇▁▁▁▇▇▇▁  (시간대 막대)
│ 요청
│  · 작업 기록 기능 기획 문서 작성
│  · 메뉴바 라벨 색상 수정
│ 커밋 3
│  · Color only the low service orange …        14:12
│  · Release 0.9.1                              15:02
│ 파일 12개 변경 (커밋 9 · 미커밋 3)
│ 영수증 1 · 기능 개발 52분
└
┌ project-b …
```

- 날짜 이동은 최근 7일까지(인덱스 보존 범위). 미래 날짜 버튼은 비활성.
- 프로젝트 정렬: 작업 시간 내림차순. 작업 시간 1분 미만이고 커밋이 없는 프로젝트는 접힌 "기타" 묶음으로.
- 요청은 프로젝트당 최대 3개, 한 줄 80자에서 자른다. "더 보기"로 최대 10개. 프롬프트 표시를 끄면(§8) 세션 제목만 보인다.
- 커밋은 제목 한 줄과 시각만. 클릭하면 해시 복사.
- 바뀐 파일은 개수만 기본 표시, 펼치면 저장소 기준 상대 경로 목록.
- 빈 상태: "오늘 기록된 세션이 없어요", git 미설치·권한 거부 시 커밋 영역에 이유 한 줄.

### 4.2 7일 탭

- 상단: 기존 7일 요약 카드(`WorkSummary`) 그대로.
- 아래: 날짜별 한 줄 — `10/17 금 · 3시간 40분 · UsageBar, project-b · 커밋 5`. 누르면 오늘 탭이 그 날짜로 이동.
- 복사: 주간 마크다운(날짜별 섹션).

### 4.3 영수증 탭

현재 `WorkJournalView` 내용 그대로(시작 카드, 진행 중 카드, 영수증 목록, 삭제). 7일 요약 카드만 7일 탭으로 옮긴다.

### 4.4 패널·메뉴

- 패널의 작업 영수증 행(`WorkJournalPanel`)은 유지하고, "작업 기록 열기" 문구로 바꾼다.
- 설정 → 작업 기록 섹션에 추가할 항목: `작업 일지 사용`, `git 커밋 포함`, `요청 문장 표시`, `제외할 프로젝트`, `작업 공백 기준(분)`.

## 5. 데이터 흐름과 모듈 경계

### 5.1 새 SwiftPM 타깃 `WorkLogCore`

```
UsageBar (앱) ──► UsageBarCore (한도·영수증)
      └────────► WorkLogCore  (일지: 의존성 없음, Foundation만)
UsageBarDoctor ─► WorkLogCore
Tests/WorkLogCoreTests
```

`WorkLogCore`는 `UsageBarCore`를 import하지 않는다. 영수증과 일지를 합치는 일은 앱 계층의 얇은 어댑터가 한다. 그래서 나중에 WorkLog 앱을 만들 때 이 타깃만 가져가면 된다. 공용 헬퍼(날짜 해석, `projectName`, 로그 루트)는 `WorkLogCore`로 옮기고, `UsageBarCore`가 그것을 쓰도록 **`UsageBarCore → WorkLogCore` 단방향 의존**을 두는 것이 권장안이다. 반대 방향 의존은 금지(열린 질문 Q6).

### 5.2 구성 요소

| 타입 | 책임 |
| --- | --- |
| `WorkLogEvent` | 정규화된 이벤트: `time`, `source`(claude/codex/git), `sessionID`, `isSubagent`, `cwd`, `kind`(`activity`/`prompt`/`fileEdit`/`commitHint`/`prLink`/`sessionTitle`), 종류별 작은 값(파일 경로, 프롬프트 위치) |
| `JSONLTailReader` | 파일 하나를 지정 오프셋부터 청크로 읽고 완결된 줄만 돌려준다. 마지막 미완결 줄은 다음 번으로 |
| `ClaudeLogParser`, `CodexLogParser` | 줄 → `[WorkLogEvent]`. 문자열 사전 필터 후 JSON 해석. 파일 단위 상태(Codex의 현재 `cwd`·서브에이전트 여부)를 커서에 보관 |
| `LogIndex` / `LogIndexStore`(actor) | 파일별 커서(경로, inode, 크기, 수정 시각, 오프셋, 파서 상태)와 날짜별 이벤트 요약을 디스크에 캐시 |
| `RepositoryLocator` | `cwd` → 저장소 루트·공통 git 디렉터리(워크트리 묶기)·표시 이름 |
| `GitHistoryReader` (프로토콜 `GitRunning`) | 하루치 커밋과 파일 수. 테스트에서는 가짜 실행기 |
| `WorkTimeCalculator` | 이벤트 시각 → 작업 구간 → 시간 합계(§6) |
| `DailyWorkLogBuilder` | 이벤트 + 커밋 + (앱이 넘긴) 영수증 요약 → `DailyWorkLog` |
| `DailyWorkLog` / `ProjectDay` | 화면·복사용 결과 모델. `Codable`, 프롬프트 본문은 포함하지 않고 위치만(§8) |
| `WorkLogFormatter` | 스크럼 3줄, 마크다운(일·주) |
| `PromptExcerpt` | 프롬프트 위치(파일, 오프셋, 길이)로 줄을 다시 읽어 첫 줄 발췌 + 비밀값 가리기 |

### 5.3 흐름

```
창 열림 / 10분 주기 / 오늘 탭 새로고침
  └ WorkLogController(앱, @MainActor)
      └ Task.detached(.utility)
          1. LogIndexStore.load()
          2. 후보 파일 열거 (수정 시각 ≥ 조회 시작, Codex는 날짜 폴더로 1차 축소)
          3. 파일별 JSONLTailReader(오프셋부터) → Parser → 이벤트 추가
          4. 인덱스 저장 (원자적 쓰기, 0600)
          5. cwd 묶음별 RepositoryLocator → GitHistoryReader (결과는 하루·HEAD 해시 기준 캐시)
          6. DailyWorkLogBuilder(날짜, 이벤트, 커밋, 영수증 요약, 설정)
      └ @Published log: DailyWorkLog, isPartial, issues
  └ 화면에서 요청 표시 직전에만 PromptExcerpt로 본문 발췌
```

## 6. 작업 시간 계산 규칙

1. **활동 시각**: 프로젝트별로 다음 시각을 모은다 — 사용자 프롬프트, 어시스턴트 응답, 도구 결과, Codex 턴 시작·종료, 커밋 작성 시각(author date). 서브에이전트 이벤트도 포함한다(사용자가 기다린 시간이므로).
2. **구간 만들기**: 시각을 정렬해 이웃 간격이 **공백 기준 G(기본 15분)** 이하이면 같은 구간으로 잇는다. G보다 길면 구간을 끊는다.
3. **구간 길이**: `마지막 − 처음 + 꼬리 T`. T = min(G, 5분) — 마지막 응답을 읽고 확인하는 시간. 이벤트가 하나뿐인 구간도 T만큼 센다.
4. **Codex 턴 보정**: `task_started`~`task_complete` 사이는 이벤트가 드물어도 하나의 구간으로 본다(긴 실행 중 공백이 G를 넘어도 끊지 않음). 상한 3시간.
5. **프로젝트 시간** = 그 프로젝트 구간 길이의 합. 같은 프로젝트의 Claude·Codex 세션이 겹치면 **합집합**으로 센다(이중 계산 방지).
6. **하루 총 시간** = 모든 프로젝트 구간의 합집합. 병렬 작업 때문에 프로젝트 시간의 합보다 작을 수 있고, 화면에 "동시에 진행한 시간 포함 안 함" 도움말을 둔다.
7. **날짜 경계**: 사용자 현지 시간대 자정. 자정을 넘는 구간은 잘라 각 날짜에 나눈다. 시간대는 시스템 기준(Codex `turn_context.timezone`은 참고만).
8. 영수증은 시간 계산에 쓰지 않는다(영수증 구간은 사용자가 누른 시작·종료라 의미가 다름). 프로젝트 카드에 별도 표시만.

검증 예시(테스트로 고정): 09:00, 09:10, 09:40 → G=15분이면 [09:00–09:10]+5분 = 15분, [09:40]+5분 = 5분, 합계 20분.

## 7. git 저장소 찾기와 읽기

### 7.1 저장소 찾기

- 입력: 이벤트에 등장한 서로 다른 `cwd` (하루 수십 개 이하).
- 파일 시스템에서 위로 올라가며 `.git`(디렉터리 또는 `gitdir:` 파일)을 찾는다. 프로세스 실행 없이 처리.
- `.git` 파일이 워크트리를 가리키면 `commondir`을 따라가 **공통 git 디렉터리**를 구한다. Claude·Codex 워크트리(`~/.codex/worktrees/…`, `.claude/worktrees/…`)의 작업이 원래 저장소 하나로 묶인다.
- 프로젝트 표시 이름: 공통 저장소의 작업 트리 폴더 이름. 저장소가 아니면 `cwd` 마지막 경로(기존 `projectName` 규칙).
- 삭제된 워크트리라 `cwd`가 없으면: Codex `session_meta.git.repository_url`의 마지막 요소, 없으면 폴더 이름으로 표시하고 커밋 영역은 비운다.

### 7.2 커밋 읽기

- 실행 파일: `xcode-select -p`가 성공할 때만 `/usr/bin/git`. 아니면 `/opt/homebrew/bin/git`, `/usr/local/bin/git` 순. 모두 없으면 커밋 기능 끔. (`/usr/bin/git`은 명령줄 도구가 없으면 설치 대화상자를 띄우므로 먼저 확인한다.)
- 환경: 빈 환경에서 `HOME`, `LANG=C`, `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`만 설정(에이전트 셸의 PATH 누수 메모 참고). `-c core.fsmonitor=false`.
- 명령(읽기 전용):
  - `git -C <root> config user.email` — 내 커밋만 보기 위한 작성자
  - `git -C <root> log --all --since=<날짜 00:00> --until=<다음날 00:00> --author=<email> --no-merges --date=iso-strict --pretty=format:%H%x1f%aI%x1f%s --shortstat`
  - 선택: `git -C <root> status --porcelain=v1 -uno` — 오늘 탭에서 미커밋 파일 수
- 시간 제한 저장소당 3초, 출력 상한 1MB. 실패하면 그 저장소만 "커밋을 읽지 못했어요".
- 캐시 키: (공통 git 디렉터리, 날짜, `HEAD`·`packed-refs` 수정 시각). 지난 날짜는 사실상 불변이라 한 번만 읽는다.

### 7.3 바뀐 파일 수

- 커밋된 파일: 그날 커밋들의 `--name-only` 합집합(중복 제거).
- 세션에서 수정한 파일: Claude `Edit`/`Write` 경로, `bashEditDiff.changedFiles`, Codex `FileChange` 키. 저장소 루트 밖 경로는 버린다.
- 표시: `파일 N개 변경 (커밋 a · 미커밋 b)`. 두 출처의 합집합이 N.

### 7.4 macOS 폴더 접근 권한(중요)

사용자의 프로젝트는 `~/Desktop`, `~/Documents`에 있다. 이 두 폴더는 TCC 보호 대상이라, UsageBar(또는 UsageBar가 띄운 git)가 처음 접근하면 **"UsageBar가 데스크탑 폴더의 파일에 접근하려고 합니다"** 대화상자가 뜬다. 세션 로그(`~/.claude`, `~/.codex`)는 해당 없음.

- `git 커밋 포함`은 기본 **꺼짐**으로 두고, 켤 때 "프로젝트 폴더를 읽기 위해 macOS가 권한을 물어볼 수 있어요"를 먼저 안내한다(열린 질문 Q2).
- 거부되면 커밋·미커밋 영역만 비우고 나머지 일지는 그대로 보여준다.

## 8. 개인정보 원칙

현재 `docs/PRIVACY.md`는 "대화 내용을 저장하지 않는다", "메시지 본문은 보관하지 않는다"고 약속한다. 일지는 프롬프트를 **보여줘야** 하므로 다음 원칙으로 이 약속을 지킨다.

1. **로컬 전용**: 네트워크 요청 없음. 일지 기능에는 업데이트 확인 외 통신 코드가 없다.
2. **본문 미저장**: 인덱스 캐시에는 프롬프트 본문을 넣지 않는다. 프롬프트 이벤트는 `(파일, 바이트 오프셋, 길이, 시각)` 위치만 저장하고, 화면에 그릴 때 원본 로그에서 그 줄을 다시 읽어 발췌한다. 원본을 지우면 일지에서도 사라진다.
3. **최소 발췌**: 첫 줄, 최대 80자. 코드 블록·붙여넣은 긴 텍스트는 "(붙여넣은 내용)"으로 바꾼다.
4. **비밀값 가리기**: API 키 모양(`sk-…`, `ghp_…`, `xox…`, `AKIA…`, 32자 이상 hex/base64 덩어리), URL의 쿼리 문자열, 이메일 주소를 `•••`로 치환. 복사 텍스트에도 같은 규칙.
5. **선택권**: 설정에서 `요청 문장 표시`를 끄면 세션 제목(`aiTitle`/`customTitle`/`thread_name`)만 보인다. `제외할 프로젝트`는 일지·복사 모두에서 빠진다. 기능 전체 끄기 가능.
6. **저장 위치와 상한**: `~/Library/Application Support/UsageBar/worklog-index/` (0700, 파일 0600), 최근 8일치만 유지, 전체 상한 20MB, 심볼릭 링크 경로 거부(`guardPath` 재사용).
7. **git**: 읽기 전용 명령만, 작성자 필터는 저장소의 `user.email`을 실행 시점에만 쓰고 저장하지 않는다. 커밋 제목은 캐시에 저장한다(원본 저장소에 이미 있는 정보) — Q4.
8. **문서**: `PRIVACY.md`에 "작업 일지의 출처" 절을 추가하고 위 내용을 그대로 적는다. README의 "저장하지 않는 것" 문구도 함께 고친다.

## 9. 성능: 큰 로그의 증분 파싱

- **후보 축소**: 파일 수정 시각 < 조회 시작이면 건너뜀. Codex는 `YYYY/MM/DD` 폴더 이름으로 1차 축소하되, 재개된 세션 때문에 시작일이 오래된 파일도 수정 시각으로 다시 포함.
- **커서**: 파일마다 `(inode, 크기, 수정 시각, 오프셋)`. 크기가 커졌으면 오프셋부터만 읽는다. inode가 바뀌었거나 크기가 줄었으면 처음부터 다시.
- **청크 읽기**: `FileHandle`로 1MB씩 읽어 줄로 나눔. 파일 전체를 메모리에 올리지 않는다(459MB 파일 대응). 미완결 마지막 줄은 커서에 남기지 않고 오프셋을 그 줄 시작에 둔다.
- **사전 필터**: JSON 해석 전에 바이트 검색으로 걸러낸다. Claude: `"type":"user"`, `"tool_use"`, `"toolUseResult"`, `"ai-title"`, `"custom-title"`, `"pr-link"`; Codex: `session_meta`, `turn_context`, `task_started`, `task_complete`, `UserMessage`, `FileChange`. `compacted`, `world_state`, `reasoning`은 해석하지 않는다.
- **첫 실행**: 7일치 전체 스캔이 필요하다. 백그라운드(`.utility`)에서 돌리고 화면에 "기록을 읽는 중…"과 진행된 날짜부터 표시. 시간 예산(창 열 때 4초)을 넘기면 `isPartial` 표시 후 다음 주기에 이어 읽는다.
- **이후 실행**: 새로 붙은 줄만 읽으므로 수 ms~수백 ms 목표.
- **목표 수치**(UsageBarDoctor로 측정): 첫 스캔 7일치 ≤ 10초(이 Mac 기준), 증분 갱신 ≤ 300ms, 상주 메모리 증가 ≤ 30MB.
- **기존 집계 이관**(선택, 0.10.x): 영수증의 토큰 집계(`LocalSessionLogs.scan`)도 같은 스캐너로 옮기면 256MB 초과 파일을 건너뛰던 문제도 풀린다.

## 10. 요청 고르기 규칙(규칙 기반)

프로젝트·세션별로 "주요 요청"을 고른다.

- 후보: 사람 프롬프트만(Claude `origin.kind == human` 또는 `origin` 없음 + `isMeta`/`isCompactSummary` 아님 + `isSidechain` 아님, `<` 또는 `/`로 시작하지 않음; Codex `UserMessage` 중 태그 주입 아님, 서브에이전트 세션 아님).
- 제외: 짧은 응답(공백 제외 12자 미만, 예: "ㅇㅇ", "ok", "좋아", "계속"), 바로 앞 요청과 같은 내용.
- 선택: 세션의 첫 요청 + G 이상 공백 뒤 첫 요청 + 커밋 직전 요청. 시간순, 프로젝트당 3개(펼치면 10개).
- 세션 제목이 있으면 카드에 제목을 먼저 보이고 요청은 그 아래.
